# Реестры планирования — полные правила (PLAN-145)

Конспект — в CLAUDE.md. Здесь детали; читать, когда меняешь сами правила или не понятно, куда что писать.

## Три реестра, одна схема

Индекс — таблица Markdown в служебном файле корня `planning/`; тело — файл в каталоге.

| Реестр | Индекс | Каталог | Файл записи |
|---|---|---|---|
| RM — идея | `ROADMAP.md` | `roadmap/` | `RM-{N}-slug.md` |
| PLAN — план | `ACTIVE_PLANS.md` (в работе), `PLANS.md` (закрытые) | `plans/` (документ), `plans/closed/` (запись о закрытии) | `PLAN-{N}-slug.md`, `closed/PLAN-{N}.md` |
| HF — хотфикс | `HOTFIXES.md` | `hotfixes/` | `HF-{N}-slug.md` |

Строка индекса: `id | название | статус | дата | влит-в | автор`; текст строки (без колонки id) ≤ 160 символов.
Статусы: RM — идея, отложена, стала PLAN-N, отклонена; PLAN — черновик, в работе, на паузе, ждёт владельца,
закрыт, аннулирован; HF — влит, откачен. Нумерация сквозная, номер не переиспользуется
(`registry.sh next-id`). Составные заголовки старого `PLANS.md` (PLAN-62/63 и т. п.) — один файл в
`plans/closed/`, остальные id — aliases в `closed/_map.tsv`. Закрытые записи НЕ переписываем: `closed/*` и
закрытые `hotfixes/HF-*` хранят тела побайтно (если есть `verify-*-migration.sh`, pre-push сверяет).

## registry.sh

`.claude/scripts/registry.sh`: `next-id <RM|PLAN|HF>` · `add <RM|HF|PLAN> <id|auto> "название" [--status S] [--date D]
[--trigger T] [--slug S]` (для PLAN регистрирует существующий документ или заводит заготовку с `## Резюме`) ·
`set-status <id> <статус>` (PLAN → закрыт/аннулирован переносит строку в `PLANS.md`, нужен `plans/closed/PLAN-N.md`) ·
`show <id>` · `check [--registry rm|plan|hf|all]`. Индексы руками не правим — Edit/Write на них блокирует
`registry-guard.sh`. Читай индекс и `## Резюме` плана, а не тела: `big-read-guard.sh` режет полный Read файла > 40 КБ или > 300 строк.

## План-документ

`PLAN-{N}-kebab.md` в `planning/plans/`, H1 с номером. Для N ≥ 145: `## Резюме` ≤ 15 строк в первых 30 строках (E7); размер
40 КБ — предупреждение, 80 КБ — блок, обход `<!-- size-waiver: причина -->` в первых 30 строках (E8). Нумерация: PLAN-N —
дизайн, PLAN-N.1 — исполнение. Superpowers-скиллы по умолчанию пишут в `docs/superpowers/` — у нас НЕ так: дизайн это раздел
внутри плана, отдельная спека не заводится. Правь план по коду, а не наоборот; `.claude/scripts/plan-code-refs.sh
planning/plans/PLAN-N-*.md` перед закрытием должен быть пуст (мёртвые имена закрытого плана — в разделе «Поправка по факту
реализации (дата)» без обратных кавычек).

## Самоповторное ревью плана

Перед показом пользователю: проход 0 без субагента — раздел «что уже есть» с путями (радиус поражения:
`.claude/scripts/blast-radius.sh <символ>`), затем проходы `deep-reasoner` по чеклисту `plan-review-checklist` (память) до
первого прохода БЕЗ блокеров (ревьюер помечает БЛОКЕР / ВАЖНО / МЕЛОЧЬ; ВАЖНО и МЕЛОЧЬ дорабатываешь сам). Ревьюеру: Резюме +
дифф + проход 0; со второго прохода — изменённые разделы и одно новое направление; список найденного передавай всегда.
Не-денежное ревью — Codex, денежное — opus и Codex (`mark-reviewed.sh --by opus|codex`).

## Ревью кода: правило остановки

- Не больше двух проходов: полный и один дельта-проход только по строкам, изменённым после находок первого.
- Чинятся только БЛОКЕРы. ВАЖНО и МЕЛОЧЬ дорабатывает автор сам, без нового прохода ревью.
- Ревьюеру на дельта-проходе передают список закрытого и одну задачу — подтвердить, что закрытое закрыто; новых направлений он не ищет.
- Денежный код: один аудит opus и один Codex параллельно, затем одна проверка правок (не новый полный круг).
- Принятый риск: защита хуков по тексту shell-команды не закрывает намеренный обход (команда собирается из кусков, динамические подстановки). Это защита от случайности агента, не от умысла — не гонять заплатки на каждый новый обход.

## Идеи RM-N

Идея, которую пока не берём в работу: `roadmap/RM-{N}-kebab.md` (H1 с номером: статус, дата, слово владельца-триггер, суть, что
известно по коду, как проверить) + строка `ROADMAP.md`. Запись — только по слову владельца («добавь в роадмап»); в `main` её
пускает маркер `rm-add` (ниже). Стала планом: статус «стала PLAN-N», в плане строка «Источник: RM-N», файл идеи не удаляем.
Коммит по идее называет `RM-N`; токен `RM-N` права менять код не даёт.

## Слово владельца (owner-ok)

Маркеры `.claude/state/owner-ok/<вид>-<id>@<ветка>` создаёт ТОЛЬКО владелец в своём терминале: `.claude/scripts/owner-ok.sh
close-plan PLAN-N | rm-add RM-N | hooks-edit <ветка>`. Агент не запускает скрипт и не пишет в этот каталог
(`owner-ok-guard.sh`). Маркер привязан к ветке и SHA её вершины, срок 24 ч, `merge-gate` забирает его атомарно (один раз).
Нужен для: закрытия плана (E10), новой идеи RM (E11), правки защищённых путей — хуки, настройки, `CLAUDE.md`, `.githooks/` (E18).

## Правила принуждения E1–E19

| Правило | Где исполняется |
|---|---|
| E1 нет прямых коммитов в `main`; пуш `main` только с мерж-коммитами впереди `<remote>/main` (`git rev-list --first-parent --no-merges`), без force/delete | `commit-gate.sh`, `branch-guard.sh`, `main-push-guard.sh` |
| E2 код только на `feature/PLAN-N-*` / `hotfix/*` (классы путей — `paths.conf`) | `commit-gate.sh`, `branch-guard.sh` |
| E3 `PLAN-N` / `HF-N` в каждом коммите с кодом; хотфикс к мержу = `hotfixes/HF-*.md` + строка `HOTFIXES.md` | `commit-gate.sh`, `merge-gate.sh` |
| E4 план вне реестра невозможен | `registry.sh check` в commit/merge-gate, `plans-drift.sh` |
| E5 схема, словарь статусов, строка ≤ 160 | `registry.sh check` |
| E6 индексы правятся только через `registry.sh` | `registry-guard.sh` (Edit/Write/apply_patch) |
| E7/E8 Резюме и размер плана N ≥ 145 | `commit_checks.py` (commit-gate, pre-commit) |
| E9 корень `planning/` — только служебные файлы | `commit_checks.py`, `plans-drift.sh` |
| E10/E11 закрыть план / добавить идею — по слову владельца | `owner_ok.py` в `commit-gate.sh`, `merge-gate.sh` |
| E12 ревью: деньги — opus и Codex, остальное — один. Ветка, где менялся ТОЛЬКО `planning/**` (закрытие плана, правки реестров), гейт и ревью не требует (HF-152); любой файл вне `planning/`, включая удаление, возвращает строгие правила | `merge-gate.sh`, `mark-reviewed.sh --by` |
| E13 стартовый набор в бюджете (CLAUDE.md ≤ 36 КБ, набор CLAUDE.md + rules + MEMORY.md + README ≤ 52 КБ) | `commit_checks.py`, `plans-drift.sh` |
| E14 не читать целиком файлы > 40 КБ / 300 строк | `big-read-guard.sh` |
| E15 те же хуки действуют на Codex | `.codex/hooks.json`, `.codex/hooks/claude-compat.py` |
| E16 хуки не обходятся `--no-verify` | `commit-gate.sh` |
| E17 номера уникальны на дереве слияния (PLAN, RM, HF) | `merge-gate.sh` → `registry.sh check` |
| E18 хуки/настройки/инструкции агента — только под `hooks-edit` | `branch-guard.sh`, `commit-gate.sh`, `merge-gate.sh` (`e18` в `paths.conf`) |
| E19 локальные git-хуки в любом терминале | `.githooks/` (`install-githooks.sh`), SessionStart-предупреждение |

Тесты хуков: `python3 .claude/hooks/test_*.py`, `python3 .codex/hooks/test_claude_compat.py`, `python3 .claude/scripts/test_registry.py`.

## Перед вопросом о мерже

Перед вопросом владельцу о мерже агент запускает `.claude/scripts/merge-ready.sh <ветка>` (сухой прогон `merge-gate`: `merge_checks.py --preflight`, маркеры не расходуются). Спрашивает слово только при READY (кроме слов владельца) — гейты, ревью и проверки после его ответа не гонять.

## Сверка при старте сессии

`.claude/hooks/plans-drift.sh` (SessionStart) сообщает: коммиты называют PLAN-N, а индекс с тех пор не трогали;
план-документ без строки; коммиты с кодом без PLAN-N/HF-N после последней правки `HOTFIXES.md`; расхождения RM; лишнее в
корне `planning/`; бюджет стартового набора. Найденное разбери до новой работы; не верь плану — проверяй код и `git log`.
Чужая работа (другие агенты, офлайн-сессии) видна только в git: поэтому токен в сообщении коммита обязателен.
