# Рабочие правила проекта

Общие для Claude и Codex. Источник правды — этот файл; память агента их не дублирует.

## База данных и тесты

- Не очищай и не пересоздавай рабочую БД без слова владельца: `migrate:fresh|refresh`, `db:wipe`, `db:seed`, `TRUNCATE`/`DROP`, `sail dusk` на рабочей базе.
- Dusk — только на `app_dusk`, PHPUnit — на `testing`. `.env.testing` нет: `artisan --env=testing` бьёт по dev-базе.
- Worktree: `vendor` клонируй (`cp -c -R`), не симлинкуй.
- Полный PHPUnit — через `.claude/scripts/quality-gate.sh` (параллельно, затем `serial-db`), флаги не дублируй. Два полных прогона разом нельзя.
- UI-фича получает PHPUnit Feature-тест и Dusk-тест; чисто бэкенд — только PHPUnit.
- Мутацию откатывай из `cp`-бэкапа, не `git checkout` (на untracked он молчит).

## Деньги и ревью

- Одно действие = результат: «нажми ещё раз» — не сценарий. На денежном пути истина — БД, не кеш. «Закончилось» определяй фактом; списание связывай с выполнением.
- Денежные развилки («списали, потом сбой/отмена/повтор» — кто платит) выноси владельцу в плане после прохода 0, до кода. Умолчание: наш фактический расход клиенту не дарим.
- Мерж денежной ветки — только при аудите opus и Codex без блокеров, CRITICAL и HIGH.
- Обычное ревью диффа — Codex (read-only); opus при блокере или если Codex недоступен. Интерфейс (Blade, Livewire-вью, JS/CSS), хуки и защитные скрипты (`.claude/hooks`, `.claude/scripts`, `.githooks`, `.codex/`) — opus и Codex оба. Ветка только из `planning/**` — без ревью.
- Новое процессное правило = хук + тест хука + адаптер Codex; текстом оно срывается.

## Ветки, мерж, планирование

- Несколько готовых веток слей в одну от свежего `main`: один полный гейт `--merge`, одно ревью, один денежный аудит на пачку.
- Мелочи ревью чини в той же ветке до гейта, без отдельного хотфикса.
- В отчёте называй ветку, не дожидаясь вопроса.
- Решение владельца (мерж, закрытие плана, коммит) давай и выбором, и точной командой отдельным bash-блоком — команда нужна, когда хук блокирует агента.
- После плана сам прогони и отчитайся: полнота против кода (grep), стыки, дубли, мёртвый код/UI, единство названий, безопасность, юр. чистота, рост БД (retention, prune), детализация.
- Новое сверяй с существующим: раздел, модель, таблица, колонка, enum, скилл. Новая таблица/колонка — только с обоснованием, иначе jsonb/enum/связь.

## UI

- Меняя раздел, роут или подпись, прогрепай `resources/views`, `routes`, `app/Livewire`, меню, `tests` по старому имени; сверь каждое попадание.
- Одно действие = одно слово везде (меню, панель, дровер, тост).
- Без эмодзи: нужен значок — heroicon из раздела.
- Заголовки обычным регистром, без `uppercase`.
- Статус фоновых операций — тост в шапке; плашек над `<h1>` и бейджей в теле страницы нет.
- Кнопка запуска страницы — в шапке, где главная.
- Пагинация: `<x-pagination>` + `WithListPagination` (50/100/200/Все, по умолчанию 50); голый `->links()` нельзя.

## Персональные данные

- Каждую фичу проверяй на закон о ПДн (152-ФЗ для РФ) на этапе дизайна: какие ПДн, основание, место хранения, оператор/обработчик, нет ли скрытого сбора. Порядок: не собирать; агрегаты; обезличивание; обработка. Хеш email — ПДн.

## Окружение

- Самодельных docker-контейнеров не заводи, только сервисы sail.
